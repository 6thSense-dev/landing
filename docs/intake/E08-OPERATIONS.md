# E08: separate Operations decisions

The existing `/portal/ops` Operations tab now reads `GET /api/ops/intake-preview` through its existing session. The endpoint uses the unchanged `require_ops` dependency: ops, founder and admin may read; other roles and anonymous clients cannot. Existing mutation handlers and database models are unchanged.

## Supplied report contract

`app.core.ops_intake_preview.project_preview(document, now=...)` validates and projects a supplied report. `load_configured_preview()` reads only a server-configured local file; no browser path is accepted. Set both `OPS_INTAKE_PREVIEW_PATH` (absolute regular file with no symlink ancestors) and `OPS_INTAKE_PREVIEW_SHA256` (SHA256 of exact file bytes) in a separately approved local environment. Neither is configured by this change. Missing configuration, invalid pins, malformed documents, future dates and expired exports produce unknowns. Reads are bounded to 8 MiB. No cloud or database export is initiated.

The fixture `backend/tests/fixtures/intake/synthetic.json` is the complete versioned example. It embeds the native `intake-accounting-import/v1` report generated by the Catalog E04–E07 import APIs, preserves its import snapshots and report digest, and records the producing Catalog revision. Native report and snapshot digests are checked. The outer `6thsense.ops-intake-preview/1` envelope includes synthetic status, generation and expiry times, the report digest, exact episode/recording/source bindings, three separate judgment arrays and a canonical document digest. Canonical digest excludes its own digest field and uses UTF-8 JSON with sorted keys, compact separators and unescaped Unicode. The separate file pin hashes the original file bytes.

Each judgment requires an episode, source digest, report digest, explicit status, evidence references and reason. Missing or conflicting judgments remain unknown. Source conflicts suppress money, legacy assertions, correction history and judgments for that row. The UI labels those suppressed legacy fields as unknown. Capture and annotation never recalculate credit. Amounts from the supplied report become decimal strings before the HTTP response and remain strings through browser rendering, including integers beyond JavaScript's exact range. Legacy marked-paid and correction counts appear separately when the source binding matches.

Correction entries are display provenance rather than financial inputs. The adapter requires each entry to have the exact native correction fields, nonnegative exact-integer amount, boolean paid assertion, unique nonempty evidence references, matching episode, unique identity and an ordered append-only `supersedes_id` chain beginning at the episode. It does not replay correction effects or any other Catalog financial rules. Current board rate labels clarify existing estimates; legacy stored values and actions are unchanged.

## Limits

Digests bind supplied content; they do not authenticate the exporter, confirm live recording bytes or establish completeness beyond the supplied report. These limits remain visible in the UI. The adapter deliberately does not replay financial rules or become a second ledger engine. Authoritative exports, production configuration and live source verification remain unavailable. The fixture is synthetic and expires September 12; deterministic tests supply September 10 as their clock. Browser freshness uses the server's remaining lifetime, clearing values on expiration, reload failure and session-change events. No production configuration, migrations, payment actions, deployment or raw-source writes occurred.
